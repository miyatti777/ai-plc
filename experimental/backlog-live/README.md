# experimental/backlog-live — BacklogLive（AI-PLC の進み具合をライブで見る・アルファ版 0.1.0-alpha）

AI-PLC の Layer の `backlog.yaml` を読んで、タスク全体と「いまどこをやっているか」を図で表示するローカル専用のビューアです。backlog を保存すると、ページを再読込しなくても数秒で表示が変わります。Claude Code デスクトップの右側（ブラウザペイン）に出しっぱなしにして使う想定です。

> ⚠️ **アルファ版です。** 画面・ファイル構成は予告なく変わります。UI は日本語だけです。

- **installer の対象外です。** `install.sh` では入りません。下の手順で、プロジェクトに手でコピーして使います
- **閲覧専用で、外部送信はありません。** 127.0.0.1 でだけ待ち受け、CDN なども読み込みません

## 入れ方・外し方

AI-PLC のリポジトリを checkout した場所で、プロジェクトのフォルダを指定してコピーします。

```bash
cp -R experimental/backlog-live <プロジェクト>/tools/BacklogLive
```

- 置き場は `<プロジェクト>/tools/BacklogLive` にしてください（`server.py` は2つ上のフォルダをリポジトリのルートとして `Flow/` を探します。AI-PLC の Stage の本文もこの場所を見ます）。`tools/` が無ければ先に作ります
- 更新するときは、古い `tools/BacklogLive` を消してからコピーし直します。外すときは `tools/BacklogLive` を消すだけです
- Claude Code デスクトップの右ペインで使うなら、プロジェクトの `.claude/launch.json` の `configurations` に次を足します（ファイルが無ければ `{"version": "0.0.1", "configurations": [ … ]}` の形で作ります）

```json
{"name": "backlog-live", "runtimeExecutable": "python3", "runtimeArgs": ["tools/BacklogLive/server.py", "--port", "8770", "--no-browser"], "port": 8770}
```

## 何が見えるか

| 場所 | 内容 |
| --- | --- |
| 上部 | scope_id・表示名・Goal、**追従中か固定か**、Stage、表示中の Layer のパス、backlog の保存時刻 |
| 「いま」枠 | `in_progress` のタスク。無ければ、依存を満たした中で優先度が最も高い未着手タスク（P0→P1→P2、同じなら backlog の順）。名前・優先度・AC 数・依存（✓は完了） |
| 帯と凡例 | 完了／進行中／実行可能／依存待ち／ブロック／除外 の件数。完了率は「完了 ÷（全体 − 除外）」で、未完了が残るあいだは 100% と出しません |
| タスク一覧 | 状態ごとの色。いまのタスクを強調し、直前のポーリングから状態が変わったタスクは数秒だけ目立たせます |

### 流れ（タスクの表示の既定）

タスク欄の右上の「流れ／一覧」で切り替えます（選んだほうをブラウザが覚えます）。「流れ」は backlog の `dependencies` から、PJ の進む順番を図にします。backlog の書き方を変える必要はありません。

- **段:** 依存の深さごとに段に分けます。1段目は依存なしで始められるタスク、同じ段のタスクは並行できます。右ペインのような狭い幅では上から下、広い幅では左から右へ並びます
- **線:** 依存を矢印で結びます。**青い線**はいまのタスクへの直接の依存、**濃い太線**は未完了を含む最も長い依存の連なり（全体の所要を決める流れ）です
- **重要度:** P0 は枠が太く、左の色帯も太く、同じ行数なら背が高い箱です。P1 は中くらい、それ以外は控えめな箱です。色は状態（完了は薄く、依存待ちは点線、ブロックは赤）です
- **箱の中:** 1行目に ID と優先度、2行目からタスク名を箱の幅で折り返して表示します（最大3行。超えた分は「…」で、全文は箱にマウスを重ねると出ます）
- **たたみ:** 最初から続く「すべて完了した段」は1本の帯に、段の中で完了・除外が4件以上あれば「完了 N件」の箱にまとめます。押すと展開し、「完了したタスクをたたむ」で戻ります
- **運用タスクは図に出しません。** 繰り返す運用タスク（`recurrence`）は依存のつながりを持たないので、段・線・最長の連なりにも入れず、図の下に「運用タスク N件は『運用・予定』のタブに出しています」と出します（押すとそのタブに移ります）
- **実行時期を待っている箱**は青い点線、依存を待っている箱は灰色の破線です（どちらも状態は「待ち」）
- 依存が循環しているときは、循環しているタスクを同じ段に並べて赤い破線で結び、凡例に警告を出します（循環の先にあるタスクは、依存の深さどおりの段に並びます）。backlog に無い依存先（SubLayer の ID など）は線を引きません

### 運用・予定（タブ）

閉じていない運用タスク（`recurrence`）があるか、まだ終わっていない Task に実行時期（`scheduled_for`）・期限（`due`）が書かれている Layer では、「流れ／一覧」の横に「運用・予定」のタブが出ます。閉じた運用タスクや、完了・除外の Task の日付しか無い Layer ではタブは出ません（選んでいた場合は流れを出します）。タブが出るときは、閉じた運用タスクや完了した日付の件数も一緒に表示します。

- **運用タスク:** 回し方（毎日・毎週・会議の後）、前回回した日、次に回す日。今日回すもの → 次に回す日の早い順 → 会議の後 → 閉じたもの、の順に並びます。回す日の決まりは 04-operation のとおりで、画面では判定しません
- **予定と期限:** まだ終わっていない Task の実行時期と期限を1件ずつ日付順に並べ、「今日より前（時期が来ている・期限を過ぎた）」「今日・今週」「この先」に分けます。週の指定（`2026-W44`）は「10/26 の週」と出し、今日を含む週は「今日・今週」に入ります。期限を過ぎたものは赤い札、読めない日付は「日付を読めない」にまとめます。完了・除外の Task の日付は件数だけ出します
- 行を押すと、そのタスクの詳細が開きます（実行の記録・時期の変更もそこに出ます）

### タスクの詳細

流れ・一覧のどちらでも、タスクの箱（行）を押すと、そのタスクの詳細が開きます（Tab で箱に移って Enter・Space でも開きます）。右ペインのような狭い幅（720px 未満）では下からのシート、広い幅では右側のパネルに出ます。

- 出るもの: ID・名前・状態・優先度・種類、説明、受け入れ条件（全文）、依存（この Task の前に終わっている必要がある Task）、この Task を待っている Task、成果物、結果、守ること（guardrails）、検証、担当・見積・開始・完了・実行した環境など。backlog に書かれていない項目は出しません
- 依存・待っている Task の札を押すと、その Task の詳細に移ります
- 閉じる: ×・Esc・詳細の外側を押す。別の箱を押すと、そちらの詳細に替わります
- 開いたまま backlog が保存されると、数秒で詳細の中身も新しい値に変わります（閉じません）。開いている Task が backlog から消えたら「この Task は backlog にありません」と出し、最後に読めた内容を残します
- 開いている Task は URL に `&task=<ID>` として残るので、再読込しても開いたままです（例: `?layer=L-1234&task=T003`）。閉じると URL から外れます。backlog に無い ID は無視します。追従で別の Layer に切り替わったときは閉じて外します
- 長い値は1項目2000字、並びは50件で切ります。成果物のパスは文字で出すだけで、開けません（ファイルを返さない作りのため）

Stage は backlog から推定します: Inception 待ち（タスク未作成）／Operation 中／全タスク完了／SubLayer で進行／中止（intent が cancelled）／全タスク除外。

## 起動と停止

**Claude Code デスクトップ（右ペイン）:** `.claude/launch.json` の `backlog-live` をプレビューとして起動します（チャットで「backlog-live を右ペインに出して」と頼めば、Claude が `preview_start` で開きます）。このエントリは追従モード（ポート 8770）です。

- 止める: チャットで「backlog-live を止めて」と頼みます（`preview_stop`）。ペインのタブを閉じるだけでは、サーバは止まりません
- 1つの Layer に固定して右ペインで見る: 先に右ペインの backlog-live を止め（8770 がぶつかるため）、ターミナルで `python3 tools/BacklogLive/server.py --layer <Layerフォルダ> --port 0 --no-browser` を起動し、表示された URL を右ペインで開きます。固定用のエントリを launch.json に置いていないのは、見る Layer が毎回変わるためです

**ターミナル:**

```bash
python3 tools/BacklogLive/server.py
```

- ブラウザで `http://127.0.0.1:8770/` が開きます。止めるときは Ctrl-C を押します。常駐はしません
- `--layer <Layerフォルダ>` を付けると、その Layer だけを**固定表示**します（下の「追従と固定」を参照）
- `--port 0` で空いているポートを使います。ポート 8770 が使用中のときは理由を表示して終了コード 2 で止まります
- `--no-browser` でブラウザを開きません。`--root <リポジトリ>` で別のリポジトリの `Flow/` を追従します
- 必要なもの: Python 3.9 以上と pyyaml。`ModuleNotFoundError: No module named 'yaml'` が出たら、`python3 -m pip install pyyaml` で入れるか、pyyaml の入った python3 で起動してください

## AI-PLC のスキルから自動で開く

`tools/BacklogLive/server.py` を置いたプロジェクトでは、`/01-collection`〜`/04-operation` の実行中に、対象 Layer が決まった時点で `http://localhost:8770/?layer=<scope_id>` を開くよう頼めます（Stage の本文は「置いてあるときだけ使える。無ければ何もしない」という扱いです）。

- 8770 でサーバが動いていれば、それを使ってタブだけ開きます。動いていなければ `backlog-live` を起動します
- そのスレッドで開いてほしくないとき（画面共有中など）は、「ビューアは開かないで」と伝えてください
- `plc-*` の補助スキルや、スキルを通さない会話では開きません

## 追従と固定

- **追従（既定）:** `Flow/` の下で、`backlog.yaml` が最後に保存された Layer を表示します。Layer は `backlog.yaml` と `intent.yaml` の両方があるフォルダです。別の Layer の backlog を保存すると、数秒でそちらに切り替わります
  - 対象外: `Documents/`・`Context/`・`Agents/` の中（大文字小文字は区別しない。Recollection の `previous` や fixture などの写しがあるため）、隠しフォルダ、symlink、未来の保存時刻
  - 新しい Layer の発見: 今日を含む新しい日付フォルダと、見つけ済み Layer の `sublayers/` の下なら数秒で表示します。それ以外の場所にできた Layer は、30秒ごとの全体走査で見つけます
- **URL で指定:** `http://127.0.0.1:8770/?layer=<scope_id>`（例: `?layer=L-1234`）を開くと、その Layer だけを表示し続けます。ほかの Layer が保存されても切り替わりません。画面上部の「Layer を選ぶ」を開くと、保存の新しい順に候補（最大40件）が出て、押すと URL が変わります。「追従に戻す」で指定を外せます
  - 指定できるのは、追従と同じ範囲で見つけた Layer の scope_id だけです。パスや `..` を含む値は受け付けず、ファイルも読みに行きません
  - 同じ scope_id の Layer が複数あるときは、候補を出して選ばせます（URL に `&at=<リポジトリのルートからの相対パス>`、例 `&at=Flow/202610/2026-10-15/xxx` が付きます。一覧から押せば1回で選べます）
  - 新しく作ったばかりの Layer が見つからないときは、全体を走査し直してから探します（5秒に1回まで）。見つからない scope_id のタブを開いたままにすると、その間は5秒ごとに全体を走査します（実測0.25秒程度）
  - スレッドごとに作業中の PJ を表示したいときは、そのスレッドの右ペインをこの URL にします
- **固定（起動時）:** `--layer` を付けて起動すると、その Layer だけを表示し続けます。このときは URL の `?layer=` も Layer の一覧も使えません

### 注意

- **追従では、並行して作業していると表示が移ります。** 別のセッションや Phase 7 の親 backlog 更新で、ほかの Layer の backlog が保存されると、そちらに切り替わります。1つの PJ を見続けたいときは `?layer=<scope_id>` を付けた URL を開いてください
- **追従と「Layer を選ぶ」の一覧には、機密の Layer も出ます。** Flow の下のどの Layer も対象です（人に見せたくない Layer の名前も含みます）。画面を共有するときは、`--layer` で共有してよい Layer に固定して起動するか、ペインを閉じてください。Registry ビューアのような伏せ字のモードはありません
- **詳細には説明・結果・成果物のパスも出ます。** 画面を共有する前に詳細を閉じてください
- **タブが見えていないと、確認の間隔が約6秒になります。** 右ペインに表示していれば2秒ごとです
- **Phase 単位（04-operation の Phase 4・5.5・7 など）は表示しません。** backlog に Phase の記録が無いためで、範囲はタスク単位と Stage の推定までです
- 保存時刻はファイルの mtime です。checkout・touch・一括整形でも変わるので、作業の証明ではありません

## Codex で見る

- Codex のアプリ内ブラウザでも使えます（`http://127.0.0.1:8770/` を開くと、backlog の保存に合わせて表示が自動で変わります）
- 開き方: ターミナルで `python3 tools/BacklogLive/server.py --no-browser` を起動し、Codex のブラウザで `http://127.0.0.1:8770/` を開きます。サイトの許可を求められたら許可してください（設定によっては求められません）。右ペインで backlog-live がすでに動いているなら、新しく起動せずに同じ URL を開けば見られます。別に起動するなら `--port 0` を付け、表示された URL を開いてください
- 拒否されたり開けなかったりした場合は、通常のブラウザで同じ URL を開き、Codex の横にウィンドウを並べてください

## 安全のための作り

- **閲覧専用です。** backlog・intent・Registry を書き換えません。GET・HEAD 以外は 405 を返します
- `127.0.0.1` だけで待ち受けます。Host ヘッダが `127.0.0.1` か `localhost` 以外なら 403 を返します（DNS rebinding 対策）
- 返すファイルは `index.html`・`app.js`・`style.css` の3つだけです。ブラウザから受け取るのは scope_id（と、重複時に見つけ済みの Layer の中から選ぶための相対パス）だけで、どちらも走査で見つけた Layer と照合してから使います。外部への送信や CDN の読み込みはありません（CSP `default-src 'self'`）
- `backlog.yaml` が壊れているときや保存の途中でも落ちません。最後に読めた内容と「読めませんでした」の帯を表示します。`intent.yaml` だけが壊れているときは、タスクを表示したまま注意を出します
- ここにある status の語彙は Registry ビューア（`experimental/registry-viewer`）と同じ値ですが、コードは import していません

```bash
python3 -m unittest discover -s experimental/backlog-live/tests   # AI-PLC のリポジトリで

```
