# ppm-collection（依頼を受けたときに既存の案件を集めて照らす）

> 論理名: SKL_plc_collection ／ 層: ポートフォリオ層 ／ 読み取り専用。`/01-collection`（1つの案件の中の資料を集める）の手前で、案件をまたいで照らす入口

- **何をするか:** 依頼の言葉を受けて、似た既存の案件を最大3件＋「どれでもない」で示し、行き先を1つ勧めて次に打つコマンドを添える。決めるのは利用者
- **いつ呼ぶか:** 新しく `/01-collection` を始める前に、自分で呼べる（Collection から自動では呼ばれない）
- **似たスキルとの違い:**
  - `plc-consult` … **1つの Layer の中**のアイデアを、その Layer の intent・backlog と照らして振り分ける。こちらは**案件をまたいで**どの案件の話かを探す
  - `ppm-scan` … Notion・Slack など**外**から、まだ一覧に無い案件の候補を拾う。こちらは**手元の** Registry と Layer から既にある案件を探す

## コアロジック（環境に依存しない）

### 1. 入力を決める

- 依頼の言葉は利用者の言葉のまま使う（要約しない）。題名があれば題名として分けて渡す
- **公開範囲（visibility）:** 依頼が私生活（家計・家・家族・健康・私用の手続き）なら `private`、それ以外は `company`。分類が結果を変えそうで迷うときだけ1問聞く。`private` の依頼は私生活の案件だけ、`company` の依頼は私生活の案件を出さない

### 2. 候補を絞る（スクリプト）

- Registry の全状態（進行中・一時停止・予定・いつかやる・済み・やめた）から、依頼の語に当たる上位10件ほどを出す。各件には、状態・Layer・当たった語と、Layer の目的（goal）・成功条件・context の要約が付く
- 短い依頼文でも当たるように、3文字以上の漢字のひと続きを2文字ずつにも分ける（カタカナは1語のまま）
- **公開範囲の手がかり:** 業務Project の表（`business_registry.py init` で作る Program など）があれば、その Program の read_domain（work／private）を使う。Program に入っていない案件は、Layer の `intent.yaml` の `membership.read_domain` に書いてあるときだけそれを使う（名前などから推測しない）
  - 業務Project の表がある DB で、どちらにも手がかりが無い案件は**名前だけ**が返る。中身を推測で補わない
  - 業務Project の表が無い DB（Program で公開範囲を分けていない導入先）では、手がかりの無い案件も `company` の依頼では中身まで読む。`private` の依頼には、`membership.read_domain: private` と書いた Layer だけが出る。**私的な Layer を仕事の依頼から外したいときは、その Layer の `intent.yaml` に `membership: {read_domain: private}` を書く**（書かないと、仕事の依頼の結果に目的・成功条件・context の要約が出る）。Layer の無い「いつかやる」の行（S-ID）は intent が無いので分けられず、仕事の依頼に名前と目的が出て、私生活の依頼には出ない
- **言い換えでもう1回（1回だけ）:** 語で当てるので、依頼が案件の名前と違う言い方（例: 打ち合わせ／会議、メルマガ／メール、呼び名／改名）だと当たらない。1回目で、目的の近い案件が見当たらない・当たった語が1〜2個だけの候補ばかり・候補が0件のときは、AI が同じ意味で案件の名前に使われていそうな語を3〜5個考えて `--text "<利用者の言葉> <足した語>"` でもう1回だけ通し、2回の候補を合わせて §3 で選ぶ。足した語は答えに1行で示す。2回目は `--top 20` まで広げてよい
- **限り:** 語で当てるので、働きが同じでも違う言葉で書かれた案件は、言い換えを足しても上位に出ないことがある。近い仕組みの案件を知っていれば、§3 で「スクリプトの候補には出なかったが近い」と1行添えてよい（名前と scope_id だけ。中身は名指しされてから読む）

### 3. 最大3件を選ぶ（AI が読む）

- 上位10件ほどの goal・成功条件・context の要約を依頼と照らし、**目的が同じか近い**ものを最大3件選ぶ。語が当たっただけで目的が違うもの（例: 同じ「請求書」でも書式の調査と入力画面の改修）は外すか、違いを書く
- 目的が近いものが無ければ「どれでもない」を1位にする。推測で1件に決めない
- 読んでよいのは、スクリプトが返した内容だけ。それ以上に Layer を開くのは、利用者が候補の1件を名指ししたときだけ（その Layer の intent・backlog）

### 4. 行き先を1つ勧める

| 照らした結果 | 勧める行き先 | 次に打つコマンド |
| --- | --- | --- |
| 同じ目的の案件が**進行中・一時停止・予定** | その Layer の続き（予定で Layer が無ければ下の「新しい Layer」で、その案件の ID を Goal に「関連: <ID>」と1行添える） | `/04-operation <Layer>`（Layer を名指しして続きから）。依頼が今の Goal を変えるなら `/plc-consult <Layer> <依頼>` |
| 同じ目的の案件が**済み** | もう済んでいる。成果を見るか、足りない分を決める | `/plc-brief <Layer>`（Layer の無い古い案件は `/ppm-registry` で scope_id を見る）。足す・直すなら `/plc-consult <Layer> <依頼>`（Re-Collection かを判定） |
| 同じ目的の案件を**やめた** | 再開するか、別の Goal で新しく作るか | 再開は `/plc-lifecycle reopen <Layer>`（先に再計画が要る）。別の Goal なら `/01-collection`（Goal に「関連: <やめた案件の ID>」と1行添える） |
| 同じ目的が**いつかやる**（S- で始まる ID）にある | その S-ID を始める | `/ppm-someday start <S-ID>` |
| どれでもなく、その場限り・汎用・自分用（RUL_plc_adaptive §0 の①） | Layer を作らない | AI-PLC を使わずにそのまま頼む |
| どれでもなく、後で読み返す・固有の文脈・人に渡す判断・取り返しにくい操作（§0 の②〜⑤） | 新しい Layer | `/01-collection Goal: <依頼>`（近い案件があれば、Goal に「関連: <ID>」と1行添えるよう勧める） |
| どれでもなく、今は着手しない将来の案件 | いつかやるに置く | `/ppm-someday <やりたいこと>` |

- 近いが目的が少し違う案件があるときは、新しく作る案を⭐にしても、その案件を「関連: <ID>」として Goal に添える候補に挙げる
- 迷ったら、影響の小さい方（既存の案件の続きにする方）を⭐にし、新しく作る方を次点に置く
- コマンドは実行環境の形で書く（Codex は `$skill-name` に読み替える。Cursor は `.cursor/` に読み替える）

### 5. 返す（ここで止まる）

利用者が理解するための画面なので、仕組みの言葉・記号・スコアの数字を出さず、自然な日本語の文で書く。

```
📍 依頼: <利用者の言葉（長ければ先頭）>

<答えの一文。例:「同じ目的の案件が進行中です。新しく作らず、その続きでやるのがよさそうです。」>

| 候補 | 今どうなっているか | なぜ似ているか |
| --- | --- | --- |
| <表示名>（<scope_id>） | 進行中／一時停止／予定／いつかやる／済み／やめた | <目的・成功条件のどこが依頼と重なるか。違いがあれば一言> |
| どれでもない | — | <新しく作るならこれ> |

| 選択肢 | 行き先 | 選んだ後に起きること |
| --- | --- | --- |
| **A** ⭐ | <勧める行き先> | <1行> |
| **B** | <次点> | <1行> |

推奨理由
- <どの候補の何と照らしたか>

A のプロンプト: <コピペ用。実際のパス・ID で>
B のプロンプト: <コピペ用>
```

- 名前だけの候補は「中身は見ていない（公開範囲が分からないため）」と添える
- 利用者の選択を待つ場面では RUL_plc_session §9.1 の質問UIも呼ぶ（判断に要る中身は質問文と選択肢の説明に入れる）

## ストレージ操作（ファイル I/O）

| 操作 | コマンド | 書き込み |
| --- | --- | --- |
| 候補を絞る | `python3 .claude/skills/ppm-collection/collect.py --text "<依頼>" [--title "<題名>"] [--visibility company\|private] [--top 10] [--exclude <scope_id>]`（`--exclude` は /ppm-someday start から来た S-ID など、候補から外す案件。重ねられる） | なし（Registry は読み取り専用。上限20件） |
| 名指しされた Layer を見る | その Layer の `intent.yaml`・`backlog.yaml` を読む | なし |

- Cursor だけの配置では `.claude/` を `.cursor/` に読み替える。DB の場所は `.claude/db/aiplc_paths.py` が決める（`AIPLC_DB`・`.ai-plc/config.yaml` を含む）。別の DB・リポジトリを見るときは `--db <DB>`・`--root <リポジトリ>`
- Layer の中身を読むのは、リポジトリの `Flow/` の下にある Layer だけ
- 返す JSON の要点: `candidates[]`（`scope_id`・`name`・`status_label`・`layer`・`program`・`matched_words`・`layer_detail`〔`goal`・`success_criteria`・`context`。読めないときは `read: false` と理由〕・`read_domain_source`〔program／intent／unknown〕）、`notes`
- Registry が開けない・語が取れないときは `notes` に理由が入る。その旨を1行で伝え、言い換えてもらうか、`/01-collection` を案内する

## 注意

- **読み取り専用。** Registry・Layer・Stock に書かない。次のコマンドは利用者の明確な実行指示があるまで実行しない（「じゃあそれで」等の同意だけでは実行しない — RUL_plc_session §7.4）
- 候補の Layer の中身（goal・成功条件・context）を、他の Layer・Stock・外部へ写さない。返すのはこの会話の中だけ
- 1回の照らしでは company と private を混ぜない（両方を見たいときは、私生活の依頼として別にもう1回照らす。私生活の案件の中身を仕事の依頼の答えに並べない）
