# pm-story｜解決策とストーリーの改訂の案（AIPM）

AIPM の19文書のうち、解決策とストーリーの文書（03_ソリューションマップ・04_ストーリーマップ（工程 solution・story））を見直すときに、改訂の範囲の案を出す操作の型です。AI-PLC の Stage は箱づくりを含めた外側の命令で、pm-story はその箱の中の文書について、どこまで直すかを示します。

**依頼文の例**：「このストーリーを2つに分けたい。直す範囲を出して」「H5 が崩れたので解決策を見直す範囲を出して」

## 使える Layer（最初に確かめる）

`python3 .claude/skills/aipm-guided/package.py op --layer <Layer> --name story.revise` を呼ぶ（入力なしでも可）。`unselected`（AIPM を選んでいない）か `held`（19文書の記録がまだ無い・選択が Hold・保存済み）なら、理由を伝えて止まる。

## 動き

| 動き | 何をするか | 書くか |
| --- | --- | --- |
| revise | 改訂の対象の文書と状態、後ろの工程で見直す文書（後ろの工程は無い）、指定した仮説 id（`hypothesis_ids`）を含む文書、やり直しになる本人の確認を返す。保存済み（archived）の文書があれば止まる | 書かない |

## 進め方

1. 見直す理由（新しい観測・崩れた仮説の id）を聞き、`--input` の YAML（`hypothesis_ids`・`reason`）で `story.revise` を呼ぶ
2. 改訂の案（何をどう直すか）と、返った範囲を本人に見せる。人物の属性や実際の反応を推測で足さない
3. **19文書はその場で書き換えない。** 書き換えると、manifest の hash・工程の時刻・本人の確認の対象が合わなくなり、直すには記録を偽るしかなくなる。改訂すると決めたら、Re-Inception（/02-inception）で改訂の Task を足し、/04-operation でその工程をやり直す

## 守ること

- pm-story は何も書かない。AI-PLC の backlog・Task の状態も変えない
- 保存済みの文書は改訂しない（止まって、工程のやり直しを案内する）
