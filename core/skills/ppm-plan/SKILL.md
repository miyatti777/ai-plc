# ppm-plan（翌日の WillDo を組む）

> 層: ポートフォリオ層 ／ 書くのは対象日の WillDo、溢れた分を送る翌日の日記、案から外した行の扱いの印（と TODO へ の行を足す雑務の節）だけ（利用者の OK の後）。関連: `/ppm-capture`・`/ppm-update`・`/ppm-close`・`/ppm-status`

- **何をするか:** 前の日の夜に、翌日に確実にやることを1枚のリスト（WillDo）に決める
- **考え方:**
  - 前日に決めた WillDo を、当日は上から淡々とこなす。WillDo は作った後、当日は増やさない（閉じたリスト）
  - 差し込みは、緊急でなければ明日以降に回す（`/ppm-capture` が日記に振り分ける）。日記に溜まった差し込みは、その日の WillDo を組むときに入る
  - 前の日の未完了は、終業（`/ppm-close`）が WillDo の行に付けた印（繰り越し・TODO へ・やめた）で扱いが決まる。週末などで間が空いても、前に WillDo を組んだ日までさかのぼって拾う
  - 1日に入る量には限りがある。空き時間と件数の上限を超えた分は、切り捨てずに翌日へ送る
- **使わなくてもよい:** First Task・Daily Task・日記のファイルは無くても組める（無いものは飛ばす）。TODO の一覧が無いときだけ、雛形から作るかを聞く

## コアロジック（環境に依存しない）

### 1. 対象日を決める

- `date +%Y-%m-%d` を単独で実行して今日を決める
- 引数に `today` か日付があれば、それを対象日にする（`today` は「朝に今日の分を作る」場合）
- 引数が無く、**今日の WillDo が無い**ときは「昨夜の計画がまだのようです。今日の分を作りますか？ 明日の分ですか？」と聞く
- 引数が無く、今日の WillDo があるときは、明日を対象日にする
- TODO の一覧（既定は `todo/todo.md`）が無ければ、同梱の雛形から作るかを聞く（勝手に作らない。作り方は下の「ストレージ操作」）。作らないと答えたら、TODO から の枠を空にして続ける

### 2. 対象日の予定を確かめる（空き時間を決める）

- 設定 `ppm.sources.calendar` が `auto`（既定）で、この環境で予定表を読める接続があれば、対象日の予定（最大20件）を読む。会議・外出の合計時間を、1日の容量（設定 `ppm.plan.capacity_hours`、既定 6 時間）から引いた残りを、その日の**空き時間**にする
  - 自分の作業のために押さえた枠など、空き時間として使える予定は引かない
  - 予定そのものは WillDo の行にしない。準備や持ち帰りの作業だけを行にする
- **空き時間は5つの欄（Daily Task を含む）の全部で使う。** 1〜5 の見積の合計を空き時間と比べる（下の5）
- 読める接続が無い・読めなかった・`off` のときは、「<対象日> は何時間くらい作業に使えますか？」と1問聞く。答えが分からなければ、設定の容量（既定 6 時間）で組む。止めない
- メールは設定 `ppm.sources.mail` が `auto` のときだけ、読める接続があれば直近2日の未読の依頼（最大15件）を候補の参考にする。既定（`off`）では読まない
- 外の情報源は読むだけで、何も書かない。読めなかったものは、案の最後に「未取得: <情報源>（理由）」と1行出す（失敗ではなく、見た範囲の報告）

### 3. 候補を集める（使えるものだけ）

| 情報源 | 取るもの | 無い・読めないとき |
| --- | --- | --- |
| First Task（既定は `todo/first_task.md`） | 「⭐ 現在のFirst Task」の下の最初の未完了の1件 | 1の欄を空にする |
| 繰り越しと差し込み（`ppm_files.py carry`） | 下の「さかのぼって拾う」の3つ: 前に WillDo を組んだ日の未完了（繰り越し）、その日から対象日までの日記の「予定タスク」の未完了、前の日以前の日記の「緊急」の未完了 | 飛ばす |
| TODO の一覧 | 進行中の未完了（案件1行）。**必須** | 上の1のとおり |
| 実行時期が来た Task | 進行中の案件の backlog で、`scheduled_for` が対象日以前の未完了の通常 Task | 飛ばす |
| AIPM の箱の期限 | 進行中の案件のうち AIPM の箱に ToDo のシートがあるものの「期限を過ぎた ToDo」「7日以内が期限の論点」（`/pm-today` と同じ選び方） | 何も出なければ飛ばす |
| 自分が関わる未完了 Task の件数 | 案件ごとの件数。WillDo の行にはしない。First Task・TODO から を選ぶとき、件数の多い案件から自分の作業を拾い直す材料にする | 飛ばす |
| Daily Task（既定は `todo/daily_task.md`） | 行の末尾のタグが対象日に当たる行 | 飛ばす |

**さかのぼって拾う（繰り越しと差し込み）:**

- 前に WillDo を組んだ日（last）を、対象日の前の日から最大 `ppm.plan.lookback_days` 日（既定 14 日）さかのぼって探す
- 繰り越し（3の欄）: last の WillDo の未完了のうち、終業で `→ 繰り越し` の印が付いた行と、**印の無い行**（終業を飛ばした日の未完了）。`→ 繰り越し: <書き直した行>` なら書き直した行を使う。`→ TODO へ`・`→ やめた` の行は入れない。Daily Task の欄の行は、`→ 繰り越し` の印があるときだけ（Daily は次に当たる日にまた入る）
- 差し込み（2の欄）: last から対象日までの日記の「予定タスク」の未完了と、last から対象日の前の日までの日記の「緊急」の未完了のうち、印が `→ 繰り越し` か無いもの。last の日の日記の行は、last の WillDo に同じ題名の行が無いものだけ（WillDo を組んだ後に `/ppm-capture` が足した行。WillDo にある行は繰り越しの側で扱う）
- last が見つからなければ、さかのぼった範囲の日記だけを読む
- 同じ題名は1回だけにする（道具が除く）。First Task と同じ行が繰り越しにあれば、1の欄にだけ置く
- 同じ仕事が2つの欄に入りそうなときは、どちらか一方にだけ置く。道具は題名が同じときしか除かないので、案を組むときに見る:
  - Daily Task の欄で `→ 繰り越し` の付いた行が、対象日にもタグで当たる → 5の欄（Daily Task）にだけ置き、3の欄には入れない
  - 「TODOから」の欄の行の繰り越し（書き直した行を含む）と、同じ案件から TODO の一覧で選び直した到達点 → 3の欄の繰り越しの行にだけ置き、4の欄にはその案件から別の行を選ばない（別の到達点にするなら、繰り越しの行を書き直す）

- backlog の Task をまとめて WillDo に写さない。例外は「実行時期が来た Task」と「AIPM の箱の期限」で、どちらも人の言葉の1行に書き直し、ID と出どころは案の表にだけ書く
- 状態が completed の候補は捨てる。Registry（`plc_query.py`）は補助で、進行中の一覧の代わりにしない

### 4. 組み立てる（この順で）

```
1. First Task      ← First Task の1件だけ。先頭に置く
2. 差し込み        ← 前の日以前の日記の「緊急」の残り（先に）、続けて間の日と対象日の日記の「予定タスク」
3. 繰り越し        ← 前に WillDo を組んだ日の未完了のうち「繰り越し」か印の無い行
4. TODOから        ← 空き時間から 1・2・3・5 の見積の合計を引いた残りがあり、件数の上限にも余裕があるときだけ、その範囲で埋める
                     順: 実行時期が来た Task（時期の早い順）→ AIPM の箱の期限（期限を過ぎた ToDo → 7日以内の論点）
                         → TODO の一覧の進行中の案件（その日に届く到達点1つに縮めた1行）
5. Daily Task      ← Daily Task のうち対象日に当たる行（文言はそのまま）
```

- 各行は下の「1行の書き方」を通してから載せる。ただし日記から来た行（2の欄の予定タスクと緊急）は、**日記の文言のまま**載せる（差し込みを受けたときに1行の書き方を通してある。道具は日記の行と WillDo の行を題名で照らして、載せ済みの行を次の計画から除くので、文言を変えると同じ行がもう一度候補に出る）。直したいときは、先に日記の行そのものを直してから載せる
- 朝に今日の分を作るとき（対象日＝今日）: 2 には今日の日記の「緊急」の未完了も先頭の近くに入れる（今日作るので例外的に入れてよい。道具に `--with-target-urgent` を付ける）。空き時間は、始める時刻から残りの時間を考えて減らす案を出す（例: 午後から始めるなら半分）。作った後は、いつもどおり当日は増やさない

### 5. 上限を確かめ、溢れた分を送る

- 件数: 1〜4 の欄（Daily Task を除く）の件数が上限（設定 `ppm.plan.max_items`、既定 10）を超えたら溢れ
- 時間: 1〜5 の欄（Daily Task を含む）の見積の合計が空き時間を超えたら溢れ。見積の無い行は、案で見積を付けてから数える
- 4 の欄は、上の2つに収まる範囲でしか入れない（足してから送るのではなく、最初から入れない）。だから溢れるのは 1・2・3・5 だけで超えるとき
- 溢れたら、まず 2 の欄の**下の行から**順に、対象日の翌日の日記の「予定タスク」へ送る（設定 `ppm.plan.overflow_rule` の `tomorrow_diary`）。送る行にも「1行の書き方」をかけ直す
- 2 の欄を全部送っても、1・3・5 だけで空き時間か件数の上限を超えるときは、**それ以上は送らずに、超えたまま案に見せて利用者に聞く**（「繰り越しが N 件・X 分あり、空き時間を Y 分超えます。どれを翌日に回すか、TODO へ戻すか、このまま入れるかを決めてください」）。決まるまで保存しない。翌日に回すと決めた繰り越しの行は、翌日の日記の「予定タスク」へ送る。TODO へ戻すと決めた行は、TODO の一覧の雑務の節へ足す（`/ppm-close` の書き方と同じ）
- First Task（1件）と Daily Task は送らない（Daily Task を減らしたいときは、Daily Task のファイルのタグを直すよう案内する）

### 6. 案を見せて OK を待つ

```
🌙 <対象日>（<曜日>）の WillDo の案

1. First Task
   - [ ] …
2. 差し込み（日記から）
   - [ ] …
3. 繰り越し（前に組んだ日の未完了）
   - [ ] …
4. TODOから
   - [ ] …   ← 出どころ: <案件の通称・Task の ID・パス>（この案の中だけ。私生活の案件は「私生活の案件」とだけ書く）
5. Daily Task
   - [ ] …

合計 N件（見積 X分）｜ 上限 <max_items>件（Daily Task を除く）
予定: Y分（読めなければ「未取得」）｜ 空き時間 Z分
1行の書き方: 当たる行 0件（全角25文字以内。Daily Task は対象外）
参考: 今日終わった仕事（WillDo の候補ではない。/ppm-close の DONE に使う）
未取得: <情報源>（理由）
（溢れたとき）⤵ M件を <翌日> の日記へ送ります: …
（2を送っても超えるとき）⚠ 1・3・5 だけで空き時間を K分超えます。繰り越しのどれを翌日・TODO へ回すか決めてください
入れなかった行: TODO へ・やめた の印の付いた行 N件（参考）

このまま確定してよいですか？（OK / 修正: <指示>）
```

- ここで**必ず止まり**、利用者の答えを待つ（RUL_plc_session §9.1 の質問UIも使う。判断に要る件数・見積・溢れの内容は質問文にも入れる）
- 案の中では出どころ（案件の通称・Task の ID・パス）を書いてよい。保存する WillDo の行には書かない
- TODO の一覧の私生活の節（既定は「進行中の私生活」）の行の案件は、出どころに通称・ID・パスを書かず「私生活の案件」とだけ書く。道具も既定ではその案件の scope・Task の ID・名前を伏せて件数だけを出す（`scheduled_today.py`・`aipm_due_items.py`・`owner_open_count.py`）。利用者がその案件を名指しして求めたときだけ `--show-private` を付けて読み、その案件の行を書き直す

### 7. OK の後に保存する

- OK をもらった**同じターンで** WillDo を保存し、溢れた分を翌日の日記に足す。案をチャットに出しただけでは終わりにしない
- 修正の指示なら直した案を見せ直し、もう一度 OK を待つ
- 修正の指示で、2の欄（差し込み）か3の欄（繰り越し）の行を**外した**ときは、外した行を黙って消さない。行ごとに次のどれにするかを利用者に聞き（質問UIでよい。まとめて同じ扱いにしてもよい）、直した案に「外した行と扱い」として並べる:
  - **翌日へ送る** → 対象日の翌日の日記の「予定タスク」に足す（溢れた分と同じ書き方）
  - **TODO へ** → 元の行に ` → TODO へ` を付け、TODO の一覧の雑務の節へ足す（`/ppm-close` の書き方と同じ）
  - **やめた** → 元の行に ` → やめた` を付ける。やめてよいかをもう一度だけ確かめてから付ける
  - 「元の行」は候補の出どころ（`carry` の各行の `date`・`from`。前に組んだ日の WillDo の行か、その日の日記の行）。印は OK の後、WillDo の保存と同じターンで Edit で付ける。印を付けた行は、次の計画で候補に戻らない
  - 緊急の行が前に組んだ日の WillDo にも入っているときは、WillDo の行の側でだけ扱いを聞く（日記の側の同じ行には聞かない・印を付けない。道具も WillDo にある緊急の行は候補にしない）
- 未承認のまま終えるときは、最後に `未保存: <WillDo のパス>` と書く
- 保存した後、「このリストは当日増やさない。差し込みは /ppm-capture へ」と一言添える

### 1行の書き方（WillDo に載せる前に必ず通す）

> 案件を知らない同僚に「今日これをやる」と言って通じる言葉で書く。ID・手順・専門用語は WillDo の外に置く。

| # | 当たる書き方 | 見分け方 |
| --- | --- | --- |
| P1 | ID を写している | `T004`・`SG2`・`US-009` のような ID を含む |
| P2 | 手順を並べている | `→` を含む、または区切った句が3つ以上 |
| P3 | 専門用語・機能名を並べている | 日常の会話に出ない語が2つ以上 |
| P4 | 時間の箱から外れている | First Task で120分超、それ以外で60分超、または見積が無い |
| P5 | 括弧の中に内訳を書いている | 括弧の中に3語以上、または数（「3件」「9本」など）が2つ以上 |
| P6 | 終わったか判定できない | 「対応」「推進」「検討」で終わり、対象が具体的な成果物でない |

- 書き直しの手順: ①状態を確かめる（completed なら捨てる）②主語を案件の通称にする ③今日の到達点1つに束ねる ④ID と内部の用語を削る ⑤見積を 30・60・90・120 分から付ける。120分で足りなければ、分けずに小さくする
- 題名は全角25文字以内
- Daily Task の行は、Daily Task のファイルの文言をそのまま使い、この書き直し（P1〜P6 と字数）をかけない。長すぎる・手順を並べているなど気になる行は、Daily Task のファイルを直すよう案内だけする
- TODO の一覧では「{通称}を進める」でよいが、WillDo に載せる日はその日の到達点に縮め、P6 をかけ直す

| 書き直す前 | WillDo の行 |
| --- | --- |
| `見積もりツール SG2 T004 の仕上げ（単価表の読み込み → 端数の丸め → 3画面の確認）:240` | `見積もりツールの計算を通す :90` |
| `US-009: チームの勉強会の実施` | `勉強会の資料を1本書く :60` |

## ストレージ操作（ファイル I/O）

### 読む

| 用途 | コマンド |
| --- | --- |
| 置き場（対象日・前の日・翌日） | `python3 .claude/skills/ppm/ppm_files.py paths --date <日付>`（`will_do`・`task_diary`・`day_dir`・`todo`・`first_task`・`daily_task` と、あるかどうか） |
| 設定（容量・上限・情報源） | `python3 .claude/skills/ppm/ppm_files.py config`（`plan`・`sources`） |
| First Task | `python3 .claude/skills/ppm/ppm_files.py first` |
| 繰り越しと差し込み | `python3 .claude/skills/ppm/ppm_files.py carry --date <対象日>`（朝に今日の分を組むときは `--with-target-urgent` も）。`carryover` が3の欄、`urgent`・`scheduled` が2の欄の候補。各行の `plan_title`・`plan_estimate_min` を使う。`set_aside` は入れない行（参考）、`last_will_do` はさかのぼって見つけた日 |
| TODO の一覧 | `python3 .claude/skills/ppm/ppm_files.py todo --json` |
| Daily Task | `python3 .claude/skills/ppm/ppm_files.py daily --date <対象日>`（`applies` が true の行。`title`・`estimate_min` を使う） |
| 実行時期が来た Task | `python3 .claude/skills/ppm-plan/scheduled_today.py --date <対象日>` |
| AIPM の箱の期限 | `python3 .claude/skills/ppm-plan/aipm_due_items.py --date <対象日>`（AIPM を選んだ Layer が無ければ「なし」。「載っていない案件 N 件」が出たら、載せるかを `/ppm-todo` で決めるよう添える） |
| 自分が関わる未完了 Task の件数 | `python3 .claude/skills/ppm-status/owner_open_count.py` |

- 置き場と見出しは、必ず共通の部品 `ppm_files` と上の道具を通して読む。パスや見出しを決め打ちしない
- 道具は読むだけ。`[ERROR]` で止まったら、その文を伝える。文に「PyYAML」とあれば環境に PyYAML が無いだけなので `pip install pyyaml` を案内し、それ以外は文に出たキー（`ppm.` で始まる名前）の設定を直すよう案内する

### 書く（OK の後だけ）

| 対象 | 書き方 |
| --- | --- |
| 対象日の WillDo | 対象日のフォルダを `ls` で確かめ、無ければ作る。本文は WillDo の雛形から作る（下の一行の出力をそのまま使う。`{{YYYY-MM-DD}}` が対象日に置き換わっている）。5つの見出し（`## 1. First Task`・`## 2. 差し込み…`・`## 3. 繰り越し…`・`## 4. TODOから…`・`## 5. Daily Task`）の下に、決めた行を `- [ ] <題名> :<見積分>` の形で書く（見出しの直下の `<!-- … -->` の行は残してよい）。振り返りの節は空のまま残す |
| 既に対象日の WillDo があるとき | 上書きしない。「既にあります。作り直しますか？」と聞き、作り直すと答えたときだけ書き直す |
| 溢れた分・翌日へ送ると決めた行 | 対象日の翌日の日記の `## 予定タスク…` の下に `- [ ] <題名> :<見積分>` を Edit で足す。日記が無ければ、日記の雛形から作ってから足す |
| 案から外して扱いを決めた行（6・7） | 元の行（前に組んだ日の WillDo か日記）の末尾に ` → TODO へ`・` → やめた` を Edit で足す（その行の他の文字は変えない）。TODO へ の行は TODO の一覧の雑務の節（既定は「いつでもいい雑務」）に `- [ ] <題名> :<見積分>` で足す |
| TODO の一覧（無いときだけ） | 利用者が「作る」と答えたときだけ、TODO の雛形から作る。雛形の例の行（架空）は、利用者に聞いてから消す |

雛形の本文を出す一行（`<名前>` は `will_do`・`task_diary`・`todo`。`todo` は日付を渡さない）:

```
python3 -c "import sys; sys.dont_write_bytecode = True; sys.path.insert(0, '.claude/skills/ppm'); import ppm_files as p; r, c = p.context(); print(p.load_template(r, c, '<名前>', '<YYYY-MM-DD>'), end='')"
```

- 行の記法は `- [ ] 題名 :見積分`（見積は省けるが、1行の書き方で付ける）。緊急の行は `（理由: …）` を付けたまま
- Cursor だけの配置では `.claude/` を `.cursor/` に読み替える

### 保存した後の報告

```
📅 <対象日> の WillDo を保存しました: <パス>
   N件（見積 X分）／ First: <1行>
   溢れて送った分: M件 → <翌日の日記のパス>（無ければ省く）
```

## 注意

- 案を見せたら必ず止まり、OK の前にファイルを書かない
- 確定した WillDo に、当日は行を足さない（差し込みは `/ppm-capture`、完了の反映は `/ppm-update`）
- 空き時間を超えるときは、TODO から の枠を足さない（切り捨てではなく、入れない）
- 外の情報源（予定表・メール）は読むだけ。読めなくても組むのを止めない
- 状態の正は各 Layer の intent・backlog。WillDo はその日の画面で、案件の行の差分（Layer と TODO の一覧のずれ）は `/ppm-todo` で扱う
