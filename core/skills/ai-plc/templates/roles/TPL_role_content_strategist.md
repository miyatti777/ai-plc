> 🏷️ **Type:** role template (focus strategy) — Stage 1（/01-collection）のFocus Strategyで選択

対象Goal: コンテンツ制作・記事・ブログ・マーケティング・ドキュメント整備。
権限: リサーチ・執筆・デザイン指示は可。外部公開はステークホルダー承認必須。DB作成・コード実行は不可。

## 分解パターン

フェーズ構造: 企画 → 制作 → 配信 → 効果測定。

| Phase | 典型タスク |
| --- | --- |
| Strategy & Planning | ターゲット定義、テーマ設計、キーワードリサーチ、競合分析 |
| Content Creation | リサーチ、構成案、執筆、編集・校正、レビュー |
| Distribution | CMS投稿、SEO最適化、SNSプロモーション |
| Analysis & Optimization | アクセス解析、エンゲージメント分析、リライト |

- SubLayer化: 異なるコンテンツ種別（ブログ/ホワイトペーパー/動画）、シリーズ等の大規模コンテンツ群、段階的な展開（基礎構築→本格運用）
- Task化: 企画系（テーマ選定・構成案・KWリサーチ）、制作系（1記事・1動画単位）、配信系、分析系（月次レポート・改善提案）
- 留意: 品質とスピードのバランス、旧コンテンツの更新計画、素材の再利用を前提に設計する
- 外部公開物は Extension: brand-guide を有効化する（system §20）

## ロール固有検証（system §18拡張）

| Level | 確認観点 |
| --- | --- |
| L1 | 事実確認（引用・数値・固有名詞）、文法・表記揺れ |
| L2 | 可読性（導入→本論→結論の流れ）、トーン・文体の一貫性 |
| L3 | ターゲット読者が最後まで読むか、読了後のCTAが明確か |

品質ゲート: 構成案承認（Inception後）→ ドラフトレビュー（Construction後）→ 公開承認（Operation前、ステークホルダー必須）。

## ロール固有NFR（system §19拡張）

| NFR領域 | 確認観点 |
| --- | --- |
| 読了率 | ターゲット読者が最後まで読みたくなる構成か |
| SEO | タイトル・見出しに検索キーワードが含まれ、発見可能か |
| ブランド一貫性 | トーン・用語・ビジュアルがガイドラインに沿っているか |
| 再利用性 | 素材が他チャネル・他用途で再利用可能か |
