> 🏷️ **Type:** role template (focus strategy) — Stage 1で専門ロールに該当しない場合のデフォルト

対象Goal: 他戦略に当てはまらないGoal、複合的なGoal、未知の領域。権限はGoalの性質に応じて判断する（読み取り+ドキュメント作成は常に可、実装系は必要時のみ）。Complexと判定したら専門ロールへの切り替えを検討する。

## 分解パターン

固定フェーズ構造を持たず、Goalに応じて分解軸を選択する。

| パターン | 適用例 | 構造 |
| --- | --- | --- |
| 時系列分解 | プロジェクト全体、段階的展開 | 準備→実行→検証→運用 |
| 機能分解 | システム開発、機能追加 | 機能A / 機能B / 機能C |
| 組織分解 | 全社展開、部門別施策 | 部門A / 部門B / 横断基盤 |
| 技術スタック分解 | 技術基盤構築 | インフラ / バック / フロント / データ |
| ハイブリッド | 複合プロジェクト | 上記の組み合わせ |

分解手順: ①Goal分析（性質・制約・成功条件）→ ②Context参照（既存PJ・組織・技術）→ ③最も自然な分解軸を選定（依存関係・並行可能性を考慮）→ ④MECEチェック（漏れ・ダブり・粒度）。

- SubLayer化: 3個以上のTaskが必要、独立した責務、委譲・並行実行可能
- Task化: 1-2日で完了、単純明快、成果物明確
- 留意: 過度な複雑化を避けシンプルさを優先。イテレーション前提で改善を重ねる

## ロール固有検証（system §18拡張）

| Level | 確認観点 |
| --- | --- |
| L1 | 完全性（必要情報が全て含まれるか）、正確性（事実・数値・固有名詞） |
| L2 | 論理一貫性（主張と根拠が矛盾なく繋がるか） |
| L3 | 受け手価値（対象者が見て役に立つか） |

## ロール固有NFR（system §19拡張）

| NFR領域 | 確認観点 |
| --- | --- |
| 読みやすさ | 文章が明瞭で構造が整理されているか |
| 論理性 | 主張と根拠の関係が明確で矛盾がないか |
| 完全性 | 必要な情報が漏れなく含まれているか |
