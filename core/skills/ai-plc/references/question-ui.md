# 質問UIで人の承認・選択を届け、回答を待つ（細則）

> RUL_plc_session §9.1 の細則。§9.1 の既定（1問ずつ・最大3選択肢・同文を会話に残す・UI 受付は回答ではない・未回答で final にしない）を主経路とし、ここは環境差・証拠の区別・取消や遅着回答の扱いを定める。

## 適用範囲

必須 Mob Checkpoint・Next Action・Backtrack・必要な Material Ambiguity など、既存規約で人の承認・選択を待つ場面に適用する。新しい承認ゲートを作らず、既存の本人指示・継続承認を取り直さない。説明設定（§7.0）が brief でも承認の判断材料は保持する。

## 環境対応

- Claude Code: 現在利用可能で用途許可のある AskUserQuestion を使う。承認と明確化質問の用途を分ける
- Codex: 現在の tool schema と実行モードを確認して許可された質問UIを使う。具体的な対応は `.agents/skills/ai-plc/references/codex-runtime.md`
- 機能なし・用途禁止・呼出し失敗のときは、原因、回答に依存する処理の保留、利用可能な環境で対象を再提示する再開方法を示す。文章だけで UI 発行/通知到達済みと報告しない。本人の明確な文章指示の効力は既存権限どおりで、UI/通知の未確認は別に残す

## 発行前に整える

成果物/差分と対象版（hash・更新時刻等）、操作範囲、選択後の動作、懸念/未確認、分かる追加費用・本人の手間をレビュー可能にする。同じ判断点の未回答質問を重複発行しない。既存 Backtrack 等で4件以上の選択肢があるときは A/B/C と追加 D/E を文章の表で全て保持し、UI は最大3件ずつの段階選択に分ける（例: 最初に「通常A/B/C」「見直しD/E」を選び、次にその中の ID を選ぶ）。グループ選択は実行/承認ではなく、最終 ID への明示回答まで待つ。

## 回答待ちとターン終了

「停止」は回答に依存する作業の停止であり、質問UIを出してすぐ final にする指示ではない。blocking 質問は本人回答を返すまで待つ。async 質問への await は発行処理の帰還までで、accepted は本人回答ではない。正規の回答待機手段があればそれを使い、未回答のまま完了報告でターンを終えない。sleep の反復・空ツール呼出し・別用途の待機ツールによる延命、UI 目的のモード切替は行わない。

**待機手段がない場合:** 質問 ID（なければ文言・対象・時刻）・質問原文と選択肢・対象版・許可範囲・未回答状態・再開先を対象 Layer の Context 等へ保存し、依存操作を保留する。終了が避けられない場合に限り、同じ質問文と選択肢・保存先・文章での回答方法を会話に残し、「回答待ちで処理を保留・UI 保持未保証」として中断報告する。保存できなければ原因と同文・再開方法を会話に残し、保存済みと報告しない。

## 回答の照合

質問 ID（取得できなければ文言・対象・時刻）、対象版、許可範囲と本人の明示回答を対応づける。UI 受付・表示・既定選択・時間経過・要求解消は回答ではない。UI 回答と対象が明確な通常会話の文章回答は同じ照合を行い、受信した回答と出典を Context 等へ保存する。対象不明・別質問への回答・対象版変更後の古い承認は流用せず、現在の差分を示し直す。明示 OK はその版/対象範囲だけ再開し、別操作の許可を増やさない。

**未回答・修正・取消:** 未回答・空回答・期限経過・中断は承認と扱わず、状態と理由を保存する。修正は内容を反映して新しい対象版を再提示、差し戻しは既存定義の Phase へ戻る。取消は当該質問を無効にし依存操作を行わない。取消済みへの遅着回答を承認にせず、中断/期限後の回答も現在の版・質問の有効性・許可範囲を確認してから扱う。再開時は保存した未回答を読み、重複 UI を避け、失効した質問だけ再提示する。通知確認の回答を設定変更や実装の承認へ転用しない。

## 通知と証拠

発行イベント、UI 受付/表示、OS 通知到達、本人回答を分ける。通知用 hook/notify 設定の存在やツール成功から OS バナー到達を推定しない。環境受入では版/ホスト・通知権限/設定・質問対象/時刻・本人の通知観測と UI 回答を記録し、未取得は未確認にする。通知/回答の不成立が Goal に必要なら未達/一部/未確認を残し、合成/静的確認で実到達を代替して完了しない。

## 質問と開始文の区別・送信前の照合（旧 session §7.4 の細則）

- UI へ送る質問文・選択肢は通常会話にも同文で残し、開始プロンプトはその後の**別項目**として同じ初回案内に添える。開始文を質問文や選択肢へ混ぜず、提示した開始文を本人回答として記録しない。非同期 UI で待つ場合も、プロンプト表示のために final で終えない
- 送信前に、次のプロンプトの全文、実行/読取案の実在入口・対象・選択後の成果、現在の停止・許可条件、段階完了と Goal 完了の区別を照合する。欠けていれば同じ応答で補い、条件不成立の実行案は理由つきで保留する。この照合は新しい Task・probe・質問票を足す工程ではなく、案内から実行権限や承認待ちを増やさない。禁止された依存先の完了待ちや証拠不変の再照合を進行案として反復しない
- 期限切れ・資料不足・対象不明のときは、不足と条件を示し、安全な読取入口（plc-brief / plc-status-audit / plc-next）か、本人が不足を指定する返信文を次のプロンプトにする。実行中は結果待ちを維持し、確認案を出すなら読取入口だけ
- 候補クリック・UI 自由文・通常チャットの「A」は入力元で分岐せず、同じ照合で扱う

## 明確な回答後

現在の有効な質問へ一意に対応する本人の明確な最終選択回答を受けたら、その許可範囲を同じ担当が実行し結果を返す（RUL_plc_session §7.4）。開始文の再送や同じ承認を要求しない。未回答/取消/対象違い/旧版/範囲外/必要権限不足を開始へ流用しない。自動完走（§10）の自動選択・仮定では質問UI/人の回答待ちを追加せず、人の明示承認が必要な境界だけ UI で待つ。
