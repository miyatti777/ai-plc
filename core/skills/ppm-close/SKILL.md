# ppm-close（終業: 今日を締めて明日を用意する）

> 層: ポートフォリオ層 ／ 書くのはその日の WillDo の振り返りと行の扱いの印、その日の日記の緊急の行の印、TODO の一覧の雑務（どれも OK の後）。関連: `/ppm-plan`・`/ppm-update`・`/ppm-status`

- **何をするか:** 1日の終わりに「今日を締めて、明日を用意する」を1回で行う
- **考え方:**
  - 続けるための鍵は手間を小さくすること。振り返りは AI が下書きし、利用者は一言直して満足度を答えるだけ
  - 未完了の行は、黙って消さない。明日に回すか、急がないので TODO の一覧へ戻すか、やめるかを利用者と決める
  - 明日に回す行は、1日回すうちに手順の羅列や大きすぎる行に崩れやすい。送る前に1行に縮め直す
- 前の日の分を翌朝に締めることもできる（引数に日付）

## コアロジック（環境に依存しない）

### 手順（この順で）

1. `date +%Y-%m-%d` を単独で実行して対象日を決める（既定は今日。引数に日付があればその日）
2. 対象日の WillDo（既定は `Flow/YYYYMM/YYYY-MM-DD/will_do.md`）を読む。**無ければ**締めるものが無いので、「この日の WillDo がありません」と伝え、明日の分を組むなら `/ppm-plan` を案内して止まる
3. **実行率を数える**（下の「数え方」）
4. **今日終わった仕事を集め直す**（WillDo を組んだ後に終わった仕事も拾うため、この時点でもう一度集める）
   - WillDo の `- [x]` の行
   - 振り返りの `### DONE（WillDo外）` に既にある行（日中に `/ppm-update` が書いたもの）
   - TODO の一覧（既定は `todo/todo.md`）の進行中の行の Layer の注記をたどり、`intent.yaml` の status が completed で `completed_at` が対象日のもの、`backlog.yaml` の Task で status が completed かつ `completed_at` が対象日のもの（WillDo に当たらないものは WillDo外 に回す）
     - `completed_at` は全部の Task に書かれるわけではない（`/04-operation` が書くのは、実行時期 `scheduled_for` のある Task などに限られる）。日付の無い完了は拾えないので、下の「利用者の言葉」で足す。拾えなかったかもしれないことを、振り返りの下書きに1行添える（「Layer の記録から拾えるのは完了日のある Task だけです。ほかに今日終わった仕事があれば教えてください」）
   - 利用者がこの会話で「終わった」と言った仕事
5. **振り返りを下書きする**（下の「振り返りの観点」）
6. **未完了の行の扱いの案を作る**（下の「未完了の行の扱い」）。対象は WillDo の5つの欄の未完了と、**対象日の日記の「緊急」の未完了のうち WillDo に同じ題名の行が無いもの**（緊急の行は実行率の外。別に一覧する）。明日に回す行・TODO へ戻す行には「1行の書き直し」をかける
7. **1つのメッセージで見せて止まる** — 振り返りの下書き、満足度の問い、未完了の行の扱いの案をまとめて見せ、利用者の答えを待つ（RUL_plc_session §9.1 の質問UIも使う。実行率と、扱いを決める行は質問文にも入れる）
8. OK をもらったら、**同じターンで**書く:
   - 振り返りを WillDo の `## 📈 振り返り` に書く
   - 扱いを決めた未完了の行の末尾に、扱いの印を書く（下の「扱いの印」。WillDo の行も、日記の緊急の行も同じ）。チェックは `[ ]` のまま
   - TODO へ戻す行を、TODO の一覧の雑務の節（案件そのものなら進行中の節）に足す
   - **繰り越す行を翌日の日記には送らない。** 翌日の `/ppm-plan` が印を読んで3の欄（繰り越し）に入れる（日記は差し込みの受け皿にとどめ、二重に入らないようにする）
9. **翌日の WillDo を組む** — `/ppm-plan` の手順を、対象日の翌日を対象にして行う（印を書いた後で行う）。`/ppm-plan` の案の確認（OK）は、振り返りの OK とは別に取る
10. **Layer と TODO の一覧のずれは書かない** — TODO の一覧の進行中の行は、このスキルでは書き換えない。ずれを見る入口（`/ppm-todo`・`/ppm-inflight`）が導入されていれば、使うよう1行で案内する
11. **報告する**（下の「返す形」）

### 数え方

```
総数   = WillDo の5つの欄の `- [ ]`・`- [x]` の行の数（Daily Task を含む）
実行   = `- [x]` の数
先送り = 総数 − 実行
実行率 = 実行 ÷ 総数 × 100（小数第1位まで）   例: 12件中 9件 → 75.0%
```

- DONE（WillDo外）と日記の緊急の行は実行率に足さない（記録だけ。緊急は「緊急: 完了 a / 未完了 b」と別に出す）
- 扱いの印を付けた行も `- [ ]` のままなので、先送りに数える

### 振り返りの観点

- **FUN:** 今日よかったこと・楽しめたこと（終わった仕事から推す）
- **DONE:** 終わった主な仕事を3〜5点（WillDo の `[x]`）
- **DONE（WillDo外）:** 今日終わったが WillDo に載っていなかった仕事。同じ通称は1行にまとめる
- **LEARN:** 思いどおりにいかなかったこと・気づき（先送りした行から推す）
- **満足度:** x/5（利用者に聞く。AI が決めない）

### 未完了の行の扱い

| 扱い | 決め方 | 行の末尾の印 | ほかに書く先 |
| --- | --- | --- | --- |
| 繰り越し | 明日もやる | `→ 繰り越し`（書き直したときは `→ 繰り越し: <書き直した行 :見積分>`） | なし（翌日の `/ppm-plan` が拾う） |
| TODO へ戻す | 急がない | `→ TODO へ` | TODO の一覧の雑務の節（案件そのものなら進行中の節） |
| やめる | もうやらない（**必ず利用者に確かめる**） | `→ やめた` | 振り返りの LEARN に `- やめた: <題名>` と1行 |

- 未完了の行を黙ってやめない
- Daily Task の欄の未完了は、扱いを聞かず印も付けない（次に当たる日にまた入る）。利用者が「明日もやる」と言ったときだけ `→ 繰り越し` を付ける
- 日記の緊急の行のうち、その日の WillDo（差し込みの欄など）にも同じ題名の行があるものは、WillDo の行の側でだけ扱いを聞き、印もそちらにだけ付ける（日記の側では聞かない・印を付けない。二重に聞かないため。翌日の `/ppm-plan` も WillDo にある緊急の行は WillDo の側で拾う）。比べるときは空白と「（理由: …）」を無視する
- 日記の「予定タスク」の行は、ここでは扱いを聞かない。WillDo を組んだ後に足された行（WillDo に無いもの）は、翌日の `/ppm-plan` が差し込みの候補として拾う
- 印を付けずに締めた行（締めるのを飛ばした日も同じ）は、翌日の `/ppm-plan` で繰り越しの候補になる
- 既に印のある行（同じ日を2回締めるとき）は、今の印を見せて変えるかだけを聞く。TODO の一覧に同じ行を2回足さない
- **同じ文言で3日以上繰り越している行**（前の数日の WillDo にも同じ題名がある）は、大きすぎる合図。今日届く所まで縮めた案を出す（やめる案に置き換えない）

### 扱いの印

- 行の末尾（見積・理由の後）に、半角の空白と `→ ` に続けて書く。例:
  - `- [ ] 週報の型を直す :30 → 繰り越し`
  - `- [ ] 議事録の様式をそろえる :90 → 繰り越し: 議事録の見出しを決める :30`
  - `- [ ] 古い表を読む :60 → TODO へ`
  - `- [ ] 書類を窓口に出す :20（理由: 締切）→ やめた`
- 印の文字（`繰り越し`・`TODO へ`・`やめた`）は変えない。道具（`ppm_files.split_disposition`）はこの3つだけを読む
- 行の元の文・チェック・見積は変えない（書き直した行は印の後ろに書く）

### 1行の書き直し（繰り越し・TODO へ戻す行にだけかける）

扱いは変えずに、書き方だけを直す。

| # | 当たる書き方 | 見分け方 |
| --- | --- | --- |
| P1 | ID を写している | `T004`・`SG2`・`US-009` のような ID を含む |
| P2 | 手順を並べている | `→` を含む、または区切った句が3つ以上 |
| P3 | 専門用語・機能名を並べている | 日常の会話に出ない語が2つ以上 |
| P4 | 時間の箱から外れている | 見積が60分を超える、または見積が無い |
| P5 | 括弧の中に内訳を書いている | 括弧の中に3語以上、または数が2つ以上 |
| P6 | 終わったか判定できない | 「対応」「推進」「検討」で終わり、対象が具体的な成果物でない |

- 手順: ①今日進んだ分を引き、**残っている到達点1つ**に絞る ②主語を案件の通称にする ③ID と内部の用語を削る ④見積を 15・30・60 分から付け直す。60分で足りなければ、分けずに小さくする。題名は全角25文字以内
- 利用者が書いた具体的な対象の名前は残す
- 書き直した行は、案の中で「元の行 → 送る行」の形で見せ、OK をもらってから書く（繰り越しは印の後ろ、TODO へ戻すは TODO の一覧に書く）
- 大きいことを理由に、勝手にやめる・TODO へ戻すに変えない

### 見せる形（手順7）

```
🌆 今日（<対象日>）を締めます

📈 実行率: <実行>/<総数>（<率>%）
振り返りの下書き:
  FUN: …
  DONE: …
  DONE（WillDo外）: …
  LEARN: …
  満足度: ?/5 ← 教えてください

未完了 N件の扱い（案）:
  - <元の行> → 繰り越し ／ TODO へ戻す ／ やめる?
    （書き直したときだけ）送る行: <書き直した行 :見積分>
今日の緊急（実行率の外）: 完了 a / 未完了 b
  - <緊急の未完了の行> → 繰り越し ／ TODO へ戻す ／ やめる?

1行の書き直し: 送る M件のうち K件を書き直し（当たる行 0件・全角25文字以内）

このまま締めて、明日の WillDo を組みますか？（OK / 修正: <指示>）
```

### 返す形（手順11）

```
✅ <対象日> を締めました
   実行率: <実行>/<総数>（<率>%）／ 満足度: x/5
   繰り越し: a件（WillDo の行に印。明日の WillDo の繰り越しの候補） ／ TODO へ戻す: b件 ／ やめた: c件
   明日の WillDo: <保存したパス、または「案の確認待ち」> ／ 明日の First: <1行>
   （ずれを見る入口があれば）Layer と TODO の一覧のずれ: /ppm-todo で確認
```

## ストレージ操作（ファイル I/O）

### 読む

| 用途 | コマンド |
| --- | --- |
| 置き場 | `python3 .claude/skills/ppm/ppm_files.py paths --date <日付>` |
| WillDo（件数・行番号つき） | `python3 .claude/skills/ppm/ppm_files.py willdo --date <対象日>`（`counts` と、各行の `line`・`disposition`。振り返りは `retrospective`） |
| 対象日の日記の緊急 | `python3 .claude/skills/ppm/ppm_files.py diary --date <対象日>` の `urgent`（各行の `line`・`done`・`disposition`） |
| 前の数日の WillDo（3日以上の繰り越しを見る） | 同じコマンドを前の日付で（無い日は飛ばす） |
| TODO の一覧の Layer の注記 | `python3 .claude/skills/ppm/ppm_files.py todo --json` の `inflight[].layer` |
| 節の名前（設定の値） | `python3 .claude/skills/ppm/ppm_files.py config` の `todo.misc_section`・`todo.inflight_sections` |

- 置き場と見出しは、必ず共通の部品 `ppm_files` を通して読む。パスや見出しを決め打ちしない

### 書く（OK の後だけ）

| 対象 | 書き方 |
| --- | --- |
| WillDo の振り返り | `## 📈 振り返り` の下の `- タスク総数: … / 実行: … / 先送り: … / 実行率: … %` の行を数えた値に、`- 満足度: … /5` の行を答えの値に Edit で置き換える。`### FUN`・`### DONE`・`### DONE（WillDo外）`・`### LEARN` の下に `- <文>` を足す（既にある行は残し、同じ行は足さない）。`### DONE（WillDo外）` の見出しが無ければ `### DONE` の節の後に足す。振り返りの節が無ければ、ファイルの末尾に WillDo の雛形と同じ形の節を足す |
| 扱いの印 | WillDo の行（`line`）、日記の緊急の行（`line`）の末尾に ` → 繰り越し`・` → 繰り越し: <書き直した行 :見積分>`・` → TODO へ`・` → やめた` を Edit で足す。行のほかの文字とチェックは変えない。翌日の日記には書かない |
| TODO へ戻す | TODO の一覧の雑務の節（既定は「いつでもいい雑務」）の最後に `- [ ] <題名> :<見積分>`、案件なら進行中の節に `- [ ] <通称>を進める` を Edit で足す。節の見出しが無ければ、足してよいかを聞いてから末尾に `## <節の名前>` を足す |
| WillDo の5つの欄 | 行を足さない・消さない。チェックは変えない（扱いを決めた行も `- [ ]` のまま。変えるのは末尾の印だけ） |

- 書くときは Edit で、決めた行だけを変える。ファイル全体を書き直さない
- 翌日の WillDo は `/ppm-plan`（`.claude/skills/ppm-plan/SKILL.md`）の手順と書き方に従う
- Cursor だけの配置では `.claude/` を `.cursor/` に読み替える

## 注意

- 手順7で必ず止まり、利用者の答えの前に書かない。振り返りの問いは1つのメッセージにまとめる
- 繰り越す行を翌日の日記に書かない（印だけ。二重に入るのを防ぐ）
- 未完了の行を黙ってやめない。1行の書き直しは書き方の修正だけで、扱いは変えない
- 今日終わった仕事は、この時点で集め直す（計画のときの「参考」を使い回さない）
- TODO の一覧の進行中の行を、このスキルで書き換えない（足すのは「TODO へ戻す」と決めた行だけ）
- 外部のサービス（タスク管理・チャット・メール・予定表）には書かない
