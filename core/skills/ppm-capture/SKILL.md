# ppm-capture（差し込みの振り分け）

> 層: ポートフォリオ層 ／ 書くのは日記・TODO の一覧・Registry のいつかやる、利用者が選んだときだけ既に組んだ WillDo の差し込みの欄（どれも1件ずつ）。関連: `/ppm-plan`・`/ppm-update`・`/ppm-status`

- **何をするか:** 1日の途中で出てきたやることを、正しい置き場に1行で記録し、振り分け先と理由を1行で返す
- **考え方:**
  - 今日やることは、前日に組んだ WillDo だけ（閉じたリスト）。差し込みで今日のリストを汚さない
  - 差し込みは基本、明日以降に回す。明日まで待てない仕事はほとんど無い。迷ったら明日
  - 今日に入れるのは「今日やらないと実害が出る」ものだけで、利用者に確かめてから入れる
- **この版で扱うのは「やること」だけ。** 会議の文字起こしやメモのような長い文脈を案件に当てて取り込む流れは、この版では扱わない（下の「入力の形」）

## コアロジック（環境に依存しない）

### 入力の形（最初に見る）

| 入力 | 扱い |
| --- | --- |
| 1〜2行の短い文（目安 120 字以内） | **やること**。下の手順で振り分ける |
| 3行以上・長い文・ファイル・貼り付けた文字起こし | 「長い文脈の取り込みは扱っていません」と1行で返して止まる（中のやることを1件ずつ渡してもらえば振り分ける） |
| 複数のやることを並べて渡された | 1件ずつ振り分け、最後に一覧で報告する |

### 手順（やること）

1. `date +%Y-%m-%d` を単独で実行して今日と明日を決める
2. 下の「1行の書き方」で、記録する1行に言い換える（振り分けより先）
3. 下の「振り分け」で行き先を決める。今日（緊急）にするときは必ず利用者に確かめる
4. 行き先のファイルに1行を足して保存する（このターンのうちに）
5. 振り分け先と理由を1行で報告する

### 1行の書き方（記録する前に必ず通す）

> 案件を知らない同僚に「今日これをやる」と言って通じる言葉で書く。ID・内部の手順・専門用語は行の外に置く。

- 形は「**{対象}を{動詞}** :{見積分}」。題名は全角25文字以内
- 1つでも当たれば言い換える:

| # | 当たる書き方 | 見分け方 |
| --- | --- | --- |
| P1 | ID を写している | `T004`・`SG2`・`US-009` のような ID を含む |
| P2 | 手順を並べている | `→` を含む、または区切った句が3つ以上 |
| P3 | 専門用語・機能名を並べている | 日常の会話に出ない語が2つ以上 |
| P4 | 時間の箱から外れている | 見積が60分を超える、または見積が無い（差し込みは15〜60分） |
| P5 | 括弧の中に内訳を書いている | 括弧の中に3語以上、または数（「3件」「9本」など）が2つ以上 |
| P6 | 終わったか判定できない | 「対応」「推進」「検討」で終わり、対象が具体的な成果物でない |

- 例外: TODO の一覧の進行中の案件の行は「{通称}を進める」でよい（P6 を当てない）。いつかやるの行は見積を付けない（P4 を当てない）。背景はメモに残す
- 言い換えの手順: ①主語を案件の通称にする ②手順を捨て「何が終わるか」1つに束ねる ③ID と内部の用語を削る ④見積を 15・30・60 分から付ける。60分で足りなければ、分けずに小さくする
- 言い換えは抽象化ではない。利用者が書いた具体的な対象（相手・案件・書類の名前）は残す。落とすのは内部の手順・ID・手段の説明だけ
- 意味が変わりそうなとき、対象が読み取れないときは、言い換えた行を見せて確かめる。元の文は報告の「元の入力」にだけ残し、ファイルの行には書かない

| 受け取った入力 | 記録する行 |
| --- | --- |
| `見積もりツール T004 の計算の修正（単価表の読み込み → 端数の丸め → 合計の表示）` | `見積もりツールの計算を直す :60` |
| `共有フォルダから来週の会議の資料を探して印刷して席に配る` | `来週の会議の資料を配る :15` |

### 振り分け

```
0. AIPM を選んだ案件の中のやること・論点か？（その案件の Layer の intent.yaml の addons に addon_id: aipm か aipm-light、
   または work_style: aipm がある。分からなければ利用者に1問）
   → はい: ここでは記録しない。/pm-suggest で候補を拾い、決めたものを /pm-todo・/pm-issue で箱の一覧に入れるよう案内して止まる
           （ToDo・論点の正本は箱の中。TODO の一覧や日記に写さない）
   → いいえ: 1へ
1. 今日やらないと実害が出るか？（基準は設定 ppm.capture.urgent_criteria。
   既定は「今日やらないと実害（他者ブロック・締切超過・信頼毀損）が出るか」）
   → 出そう: 利用者に「これは今日中でないと実害がありますか？」と確かめる
      → はい: 今日の日記の「緊急」に、理由を1行付けて書く
              （緊急の行は /ppm-status が表示し、/ppm-update が完了の印を付け、/ppm-close が扱いを決め、
               残りは次の /ppm-plan で差し込みの候補になる）
      → いいえ: 2へ
2. 期日・やる日が決まっているか？
   → 決まっている（明日・指定日）: その日の日記の「予定タスク」へ
   → 決まっていない:
      - まだ手を付けない将来の案件（やるなら Layer を作る規模）→ いつかやる（Registry に登録。TODO の一覧には書かない）
      - 既に動いている案件そのもの → TODO の一覧の進行中（通称の1行。同じ通称があれば足さない）
      - 1回の作業で終わる小さなこと → TODO の一覧の雑務
3. 迷ったら明日の日記の「予定タスク」へ
   今日の WillDo の5つの欄には、下の「行き先の日の WillDo が既にあるとき」で利用者が選んだときを除いて足さない
```

**行き先の日の WillDo が既にあるとき**（日記の「予定タスク」へ書く場合。終業の後に明日の WillDo を組み終えてから「明日やる」が来たとき、急ぎではないが今日やると言われたときなど）:

- 日記に書く前に `ppm_files.py paths --date <行き先の日>` の `will_do` の `exists` を見る。あれば「<その日> の WillDo はもう組んであります」と伝え、どちらにするかを聞く（質問UIでよい）:
  - **A. その日の WillDo の「2. 差し込み」の欄に足す** — その日のリストに入る。日記には書かない（二重に入らないように）
  - **B. 日記に置いて、次の計画で拾う** — その日の WillDo には入らない。次に `/ppm-plan` で組む日（その日の翌日以降）の差し込みの候補になる。それまでは `/ppm-status` が「日記に後から入った予定」として見せる
- 行き先が明日以降なら A をすすめる。行き先が今日なら B をすすめる（今日の WillDo は当日増やさないのが基本。A は利用者が選んだときだけ）
- 緊急（今日の日記の「緊急」）は、この問いをせず今までどおり日記に書く（WillDo には足さない）

- いつかやると雑務の分け方: 1回の作業で終わる → 雑務 ／ 手を付けるなら Layer（`/01-collection`）を作る規模 → いつかやる

### 返す形

```
📥 <振り分け先> に記録しました
   やること: <言い換えた行 :見積分>
   元の入力: <言い換えたときだけ>
   理由: <実害なし→明日 ／ 期日あり→その日 ／ 期日なし→TODO ／ 将来の案件→いつかやる ／ 緊急（理由）→今日>
```

## ストレージ操作（ファイル I/O）

| 行き先 | ファイルと節 | 足す行の形 |
| --- | --- | --- |
| 今日（緊急） | 今日の日記（既定は `Flow/YYYYMM/YYYY-MM-DD/task_diary.md`）の `## 緊急…` | `- [ ] <やること> :<見積分>（理由: <今日やらないと出る実害>）` |
| 明日・指定日 | その日の日記の `## 予定タスク…`（その日の WillDo が既にあり、利用者が A を選んだときは、その WillDo の `## 2. 差し込み…` の欄の最後） | `- [ ] <やること> :<見積分>` |
| 期日なし・案件 | TODO の一覧（既定は `todo/todo.md`）の進行中の節（既定は「進行中の仕事」。私生活なら「進行中の私生活」）。小区分（既定は「主軸」「支援課題」）があればどちらかを利用者に聞く | `- [ ] <通称>を進める`（Layer があれば次の行に字下げして `<!-- layer: <Layer のパス> scope: <Scope ID> -->`） |
| 期日なし・雑務 | TODO の一覧の雑務の節（既定は「いつでもいい雑務」） | `- [ ] <やること> :<見積分>` |
| いつかやる | Registry（`.claude/db/ai_plc.db`） | `python3 .claude/db/plc_query.py someday-add "<やりたいこと>" "<メモ>"`（S- で始まる ID が付き、予定〔planned〕で登録される。一覧は `/ppm-someday`） |

### 置き場の見つけ方と書き方

- 置き場と見出しは、必ず共通の部品 `ppm_files` を通して読む。パスや見出しを決め打ちしない
  - 日の置き場: `python3 .claude/skills/ppm/ppm_files.py paths --date <その日>` の `day_dir`・`task_diary`
  - TODO の一覧の節と行番号: `python3 .claude/skills/ppm/ppm_files.py todo --json` の `sections[]`（`name`・`line`・`kind`・`subgroups`・`items`）
  - 節の名前（設定の値）: `python3 .claude/skills/ppm/ppm_files.py config` の `todo.inflight_sections`・`todo.work_subgroups`・`todo.private_sections`・`todo.misc_section`
- 行は、その節（小区分があればその小区分）の最後の行の後、次の見出しの前に Edit で足す。ほかの行は変えない
- **日記が無いとき:** その日のフォルダを `ls` で確かめ、無ければ作る。日記は雛形から作る。本文は次の出力をそのまま使う（`{{YYYY-MM-DD}}` がその日に置き換わっている）。その後で行を足す
  ```
  python3 -c "import sys; sys.dont_write_bytecode = True; sys.path.insert(0, '.claude/skills/ppm'); import ppm_files as p; r, c = p.context(); print(p.load_template(r, c, 'task_diary', '<YYYY-MM-DD>'), end='')"
  ```
- **TODO の一覧が無いとき:** 勝手に作らない。「TODO の一覧（<置き場>）がまだありません。同梱の雛形から作りますか？」と聞く。作ると答えたら、上と同じ一行の `'task_diary', '<YYYY-MM-DD>'` を `'todo'`（日付は渡さない）に替えた出力で作る。雛形の例の行（架空）は、利用者に聞いてから消す
- **節の見出しが無いとき**（区分を使わない TODO の一覧など）: 雑務・進行中の節が無ければ、ファイルの末尾に `## <設定の節の名前>` を足してよいかを聞いてから書く
- いつかやるの登録は `plc_query.py someday-add` だけで行う（SQL で直接足さない。Layer のフォルダは作らない）
- Cursor だけの配置では `.claude/` を `.cursor/` に読み替える

## 注意

- WillDo の5つの欄には、上の「行き先の日の WillDo が既にあるとき」で利用者が A を選んだときの「2. 差し込み」の欄を除いて足さない（日中の完了の反映は `/ppm-update`）
- 今日（緊急）にするのは、利用者が「はい」と答えたときだけ。理由の無い緊急は書かない
- 書く前に必ず「1行の書き方」を通す。利用者の書いた具体的な対象の名前は削らない
- 長い文脈（会議の記録・文字起こし）を案件へ取り込む流れは、この版では扱わない。Layer の Documents に手で置くか、`/04-operation` の作業として扱う

## 次のアクション

返答の最後に「次のアクション」と、コピーして送れる「次のプロンプト」を付ける（RUL_plc_session §7.4）。

| 状況 | 次の入口 |
| --- | --- |
| 続けて今日のリストを進める | `/ppm-status today` |
| 明日の分を組む | `/ppm-plan`（日記の予定タスクが明日の WillDo の「差し込み」に入る） |
| いつかやるに入れた案件を始める | `/ppm-someday start <S-ID>` |
| AIPM の案件のやることだった | `/pm-suggest <Layer のパス>` |
