# 通常3Phaseの表示補助（Codex限定）

この資料は表現の骨格・例・送信前照合であり、Stageの手順・新mode・実行許可を定めない。正は [共通session §7〜9](../../../../.claude/rules/ai-plc-session.md)、[Inception](../../../../.claude/skills/ai-plc/02-inception/SKILL.md)、[Operation](../../../../.claude/skills/ai-plc/04-operation/SKILL.md)。上位/本人指示と正本を優先する。現行のSKILL入口と正本読取経路は保持する。

## 適用する前に

Nextの正式入口・対象・得る成果と工程停止/Goal完了の区別は共通session §7.4を優先する。以下のA/B/Cは固定候補ではない。未完Goalのある工程停止に終了案を追加せず、実行/読取案へ同名の `$skill` と実在対象を付ける。真の完了・本人保留取消・承認回答・結果待ちは状態別の返信文とし、操作コマンドを捏造しない。

対象は通常02-inception Phase4/Phase6と04-operation Task最終報告だけ。今回の表示契約として表の列名・必須ブロック順を具体化し、既存sessionの4パート/Next/Mob CPを補助する。他Stage・plc-consult/plc-brief・途中報告には追加しない。対象外でも正本に既にある要件を消さない。 承認案の初回提示は、質問UIを呼ぶ前からPhase4の提示として本資料を適用する。この提示をPhase3完了通知や対象外の途中報告として扱わない。

本人の主観的採否待ち、開始先不明、中断/期限、partial/blocked、auto/forceでは、それぞれの停止/進行契約を優先する。特に本人採否を⭐で代行せず、開始先がなければ仮Task/開始文を作らない。根拠がない⭐を必須にしない。auto/force中に本資料の例から新しい承認待ちを作らない。確認済みの承認を聞き直さず、事実の不足は未確認として示す。

表/見出しを文章リストに置き換えず、必要な列と行を保持してセル内を簡潔にする。照合結果自体を長い質問票へしない。以下の角括弧は実在するintent/backlog/証拠から埋める変数であり、例の値を転用しない。

## 質問UIより先に本文を提示

既存の人の判断点では、次の順序で進める。新しい承認・選択・待機を追加する指示ではない。

承認前は、冒頭の宣言形ブロック「🙋 **承認対象・未承認**」→「📍 [Scope] > Stage 2: Inception > Phase 4」→8列Task表→戦略と推奨根拠→セッション分割→承認後フロー→前提・未確認・費用・本人判断の順を、UI前の同じ本文に保持する。対象版・範囲と各回答の結果は宣言として記載し、本文で問いかけない。実値以外の見出し・列名・順序はP-preと揃える。

1. 該当Phaseの判断材料本文（表・理由・見積・対象版/範囲・未確認、Nextが適用される場合の開始文）を、通常会話の許された非終端メッセージへ先に出す。ファイル保存・リンクだけ・質問文だけでは本文表示の代替にしない。
2. 本文を会話へ出してから、同じ質問文・選択肢を許可された質問UIへ送る。UIの受付・既定値を回答とせず、回答待機・保存・文章再開は共通session §9.1に従う。
3. UI回答後に本文を後出しして、初回の本文提示・順序が成立したと扱わない。欠落した初回原文を保持し、判定のために再生成しない。

上位規約が非終端での質問を禁じる場合も、承認前の宣言形ブロック・対象版/範囲・回答別の結果・Phase4表示を削除または後回しにしない。問いかけだけを許可されたUIと§9.1の文章再開表示に残す。他の判断点でも、許された判断材料本文を先に示す。判断材料自体も表示できない場合は制約を記録し、本文表示・順序を未確認として依存操作を保留する。既承認・auto/force・本人の停止指定をこの節で変更しない。

UI前に承認前本文を一度確定し、対象版を変えない未回答/中断時の再掲では、その本文を見出し・順序・文言ごとそのまま使う。UI後に別形式の承認前本文を作り直さない。共通session §9.1が要求する質問原文・選択肢・未回答/再開情報は、本文とは別欄に同文で添える。再掲を新しい初回提示や実表示成功の証拠にしない。本人の修正回答による新版・承認回答後の別Phaseは、この同版再掲とは区別する。

## C：送信前照合（各Phaseに適用）

1. Stage/Phase/本人指定の停止条件を先に判定。該当するP-pre/P-post/P-taskとEの同Phase部分だけ読む。 承認案の初回本文はUI前からPhase4として照合し、Phase3完了の表示で代替しない。
2. 必須ブロック・表列・行・配置を照合し、欠落があれば送信前に補う。preは宣言形の承認対象・未承認→Phase4位置→8列表→戦略/分割/承認後フロー/境界。同版の未回答時再掲はUI前の確定本文と同文にし、質問原文等は別欄に残す。post/taskは冒頭Next表→独立理由→plain開始文→位置→4行サマリ→残りの該当ブロック。
3. Next適用時は3列・選択後の結果・妥当な⭐・理由・実在開始文を同じ初回案内へ含める。開始先不明/主観採否待ち等では必要な例外を優先し、架空の次Taskを作らない。
4. 証拠と実値を確認し、ACの4値、成果の存在、承認/質問UI/実モデルの未確認を残す。旧固定採点の意味を変えない。
5. 上位/本人/共通正本と衝突する補完をしない。照合だけで登録/実行/承認や実証済み安定性を増やさない。新しい測定/質問/待機/試行を増やさない。
